# Trader pain points: trading journals and portfolio trackers

Desk research, 2026-11-23. Every URL below was returned by a search or fetched during this research. Quotes are verbatim or close paraphrases of the fetched page.

**Caveats on the sources:**
- Reddit could not be fetched directly or found through search engines. Reddit voices come only through a mirror (`reddit.sudovanilla.org`) and a review aggregator (GummySearch).
- Several sources are vendor blogs (TradesViz, QuantWheel, StonkJournal, PurePowerPicks). They are marked **[vendor]**. Treat their framing as biased, but the concrete failure cases they describe are still useful.
- Trustpilot reviews are individual anecdotes.

---

## 1. Broker import and data ingestion

1. **Sync drops the closing legs, so closed trades look open.** A TraderSync user reports: "The platform properly synced the opening legs but completely dropped the closing executions." A closed SPX spread was left showing as open. https://ie.trustpilot.com/review/tradersync.com
2. **CSV import silently corrupts quantities.** A TraderSync user says it was "randomly reducing the size by 10x on some of the trades on the CSV file." The same user reports that "sometimes it adds a USD/GBP conversion on and other times it doesn't." https://ie.trustpilot.com/review/tradersync.com
3. **Broker formats drift without notice. [vendor]** TradesViz saw a broker that "changed its CSV column order with no announcement and no changelog," and another that "silently changed its timestamp format mid-quarter." It lists the hard cases as futures rollovers, splits, multi-leg option assignments, partial fills across accounts and prop-firm commissions. https://www.tradesviz.com/blog/state-of-journaling-2026/
4. **Nobody wants to deal with files, and most brokers have no API. [vendor]** TradesViz writes: "No one wants to work with csv/excel etc." and most brokers "do not have an open API." Sync availability is a deciding factor, and some users switched brokers because of it. https://www.tradesviz.com/blog/state-of-journaling-2023
5. **IBKR FX conversions are not imported.** Portfolio Performance (PP) skips IBKR Flex trades with `assettype="CASH"` and IB-app `FXCONVERT` operations. Non-base-currency cash accounts then go negative, and users enter these trades by hand. https://forum.portfolio-performance.info/t/interactive-brokers-import-issues-with-currency-buy-sell/8138
6. **IBKR stock grants are ignored.** PP "just ignores" `StockGrantActivity` in the Flex XML, so 11.2 shares are imported where IBKR reports 15. One user says: "I cannot reconcile my account." https://forum.portfolio-performance.info/t/importing-awarded-shares-from-ibkr/28671
7. **Duplicate detection is wrong in both directions.** Ghostfolio's open issues include #7728, where duplicate detection matches across *different accounts*, and #7406, where identical activity imports are saved without a duplicate error. https://www.GitHub.com/ghostfolio/ghostfolio/issues
8. **Dates and symbols break CSV import.** Wealthfolio's open issues include #171 "Importing Activities shows the wrong dates", #172 "'Smart' date detection", #175 "Skip symbol lookup for CSV import" and #177 "Unable to import CSV". https://issues.ecosyste.ms/hosts/GitHub/repositories/afadil%2Fwealthfolio/issues
9. **The ecosystem keeps building per-broker converters.** Export-To-Ghostfolio exists only to turn 26 brokers' CSVs into one format. Each broker has its own quirks: separators must be converted, Swissquote must be set to English, IBKR needs specific Flex columns, and ISIN-to-ticker lookup is ambiguous (an ISIN may return `VWRL.L` by default, so an override file is needed). https://github.com/dickwolff/Export-To-Ghostfolio
10. **Delisted securities disappear from T-Invest (Tinkoff).** The API "не возвращает историю по бумагам, которые больше не обращаются на бирже" (does not return history for securities no longer traded). Split ratios are not reported. FIGI changes at a split give a negative share count, for example STX. Margin fees are "не привязана к конкретному figi" (not tied to a specific instrument). https://habr.com/en/articles/589865
11. **API and app disagree in T-Invest.** A gifted share shows in the app but not in `get_portfolio()`. TCSG uses different FIGIs for the security and its operations. Free spin-off shares (Organon from Merck) have a zero cost and break the return calculation. `Tax Coupon` operations have no linked security. https://habr.com/ru/post/572358
12. **Russia has almost no broker sync.** In Russia there is "фактически нет синхронизации брокерских счетов со сторонними сервисами" (effectively no syncing of brokerage accounts with third-party services). Users can either import reports, if the service parses that broker's format, or enter trades by hand, which "занимает много времени" (takes a lot of time). Each broker has its own report. https://t-j.ru/investment-accounting/
13. **Cost basis is lost on transfers between brokers.** T-Invest did not record the purchase price of transferred-in securities without "оригиналы документов от предыдущего брокера" (original documents from the previous broker). Otherwise "налог удержится со всей суммы продажи" (tax is withheld on the whole sale amount). https://vc.ru/claim/562978-tinkoff-obmanyvaet-s-uchetom-rashodov-po-cennym-bumagam
14. **Phantom sales appear in broker reports.** Sanctions forced a depository transfer, and leftover REPO deals created a sale with a taxable gain the client never made. The broker's position: "Ими торговал брокер… Но налог будете платить ВЫ" (the broker traded them, but you will pay the tax). A journal has to be able to flag and annotate broker-originated events. https://vc.ru/884055-pribyli-net-no-nalog-est

## 2. Options, partial fills and corporate actions

15. **Each leg is journaled as its own trade. [vendor]** Most journals "treat each contract as a separate trade, which destroys any meaningful P&L tracking." Other common failures: ignoring the ×100 multiplier, mixing strikes and expiries, and missing "expiration events, assignment, and exercise." Users want win rate by strategy, for example iron condors versus naked puts. https://stonkjournal.com/articles/best-options-trading-journal
16. **Wheel traders lose the thread through assignment and rolls. [vendor]** Brokers do not "connect a put sale to its assignment to the subsequent covered call". A roll appears as two unrelated transactions, and cost basis is not adjusted on assignment. Spreadsheet upkeep is quoted at "30 to 45 minutes per day." https://quantwheel.com/learn/options-position-tracking-tools/
17. **Multi-leg entry is manual in Edgewonk. [vendor]** "each leg of a multi-leg position has to be entered by hand"; options support is "generic." https://purepowerpicks.com/edgewonk-review/
18. **DIY P&L in Obsidian breaks on scale-ins.** The template "cannot handle complex trades with multiple entries and exits." The author converts option contracts to share counts by hand. Edgewonk was rejected because "it does not handle options." https://forum.obsidian.md/t/stock-trader-daily-note/56136
19. **Splits produce fake losses.** A 1:40 split showed a false £30,000 loss because of stale Yahoo historical quotes. Mergers have to be booked by hand as "sale of old stock and buy of new stock." https://forum.portfolio-performance.info/t/stock-split-and-merger/10488
20. **Spin-offs never get settled.** PP's German thread "Wie bilde ich korrekt einen Spin-off ab?" (how do I record a spin-off correctly?) runs past 16 pages. https://forum.portfolio-performance.info/t/wie-bilde-ich-korrekt-einen-spin-off-ab/4677?page=16
21. **Historic values ignore splits.** Wealthfolio has #146 "Historic values of stocks do not reflect stock splits" and #163 "How to get correct post split stock prices." https://issues.ecosyste.ms/hosts/GitHub/repositories/afadil%2Fwealthfolio/issues

## 3. P&L and cost-basis disputes, fees and tax

22. **Different jurisdictions need different cost-basis methods on the same lots.** A US/Canada filer needs lot booking for the US and average cost for Canada. He considered separate ledgers and wrote a `parallel_average_cost` plugin. Average-cost booking had been rolled back from Beancount v3. A reporting-currency conversion (USD to CAD) is also needed. https://groups.google.com/g/beancount/c/UcEqxDKtqB8
23. **It is unclear whether fees belong in the cost basis or in expenses.** Beancount "doesn't have good support for factoring trading commissions into capital gains". The workaround folds commissions into the per-unit basis with the `{200 # 9.95 USD}` syntax, which has precision problems. https://groups.google.com/g/beancount/c/7i0T7eqppY0/m/asOX9AjRDgAJ
24. **Statistics are computed wrong.** TraderSync "printed that massive number directly into the Average Loss field" (a total was shown as an average). Another user says "applying the wrong currency base to both auto and manual trades… messing up commissions, fees, profit calculations." https://ie.trustpilot.com/review/tradersync.com
25. **The journal does not match the broker's tax form.** The 1099-B differs from the transaction list because of wash-sale adjustments, option trades that are not reported, and non-covered lots. The advice is to "compare the two side by side." https://ttlc.intuit.com/community/taxes/discussion/re-why-would-my-1099-b-be-a-different-amount-than-my-transactions-list-if-it-s-suppose-to-track/01/3558584
26. **Russian 3-NDFL with a foreign broker is heavy manual work.** Every operation must be converted "на дату платежа по курсу ЦБ РФ" (at the Central Bank rate on the payment date), and there can be hundreds of operations. FIFO lots are mandatory. Shared commissions are split in proportion to income type. Readers still ask whether to use the trade date or the settlement date (T+2). https://t-j.ru/dohod-ot-inobrokera/
27. **Home-made IBKR-to-3-NDFL scripts encode guesses.** One script fills weekend gaps with the previous CBR rate. It hard-codes 10% US withholding, assumes EUR dividends are untaxed ("taxation was NOT applyed"), derives the country code from the ISIN prefix, and marks the income code `22` "check it out". https://smart-lab.ru/blog/692506.php
28. **Tax and price edge cases in a T-Invest tool.** At first, losses did not reduce the computed tax, and readers caught the bug. With W-8BEN, 10% US withholding still leaves 3% for the investor to declare and pay, and the tool did not model that. Python's banker's rounding drifts by cents from the broker's app. The bond price from the API excludes accrued coupon (НКД). https://habr.com/ru/post/572358
29. **Users distrust the broker's own return numbers.** One reader writes: "Приложение брокера считает криво" (the broker's app calculates it wrong). They want purchase dates and costs and a portfolio return. https://t-j.ru/kakuiu-programmu-dlia-ucheta-dokhodnosti-investitsii-vybrat/
30. **Kazakhstan has its own declaration.** Residents holding foreign securities through IBKR and similar brokers file form 270 and pay 10% income tax (ИПН) on gains and dividends by September 25. They also declare foreign accounts above 1,000 МРП (monthly calculation index units). Freedom Global accounts count as domestic. https://www.nur.kz/nurfin/fines-and-taxes/2282367-kak-ponyat-nuzhno-li-sdavat-deklaraciyu-iz-za-akciy-v-kazahstane/

## 4. Multi-currency, dividends and withholding

31. **Dividends are double-taxed but have one tax field.** Foreign withholding plus local tax cannot be split in PP, and negative dividend lines are rejected. A commenter replies: "PP isn't a tax tool." https://forum.portfolio-performance.info/t/how-to-distinct-foreign-and-local-taxes-on-dividends/39254
32. **FX valuation bugs.** Wealthfolio has #181 "Use historical exchange rates to calculate balances", #168 "Showing wrong currency value at Holdings", #134 "Continued issue with GBP prices" (the pence vs pounds problem) and #106 "Issues with accounts in other currencies". https://issues.ecosyste.ms/hosts/GitHub/repositories/afadil%2Fwealthfolio/issues
33. **Trade currency differs from dividend currency.** Some shares trade in RUB but pay dividends in USD, so the author added a "валюта дивидендов" (dividend currency) column. TCS and TCSG shared one FIGI, so the FIGI had to be chosen by currency. https://habr.com/en/articles/589865
34. **Mainstream trackers get currencies wrong.** A Reddit review aggregated by GummySearch says of Yahoo Finance: "the currencies can sometimes be messed up." https://gummysearch.com/tools/best-products/portfolio-trackers/
35. **Multi-broker, multi-market tracking breaks local tools.** One user says "каждый брокер представляет свой отчет" (each broker provides its own report). Local services do not cover foreign assets: Intelinvest has "нет никаких данных, кроме текущей цены" (no data except the current price) for European bonds. https://t-j.ru/investment-accounting/

## 5. Manual entry, upkeep and why people stop journaling

36. **Avoidance after losses.** People quit because they doubt the journal works ("I don't think it's really helping me") and because "the journal becomes a mirror they'd rather not look into". Others say: "It feels like extra work after a bad day." https://theperceptivetrader.substack.com/p/why-most-traders-quit-journaling
37. **Statistics on too little data. [vendor]** New traders want day-of-week and hour-of-day breakdowns from far fewer than 1,000 executions. Users cancel when one month of imported data doesn't give a year of insight. DIY setups cost "two hours every few days, forever." https://www.tradesviz.com/blog/state-of-journaling-2026/
38. **The tool becomes the hobby.** In Obsidian, one trader was "spending more time maintaining my obsidian setup than reviewing my trades". Another warns: "you'll likely end up spending more time on Obsidian than you will with charts." https://forum.obsidian.md/t/traders-share-how-youre-using-obsidian/72606
39. **Spreadsheets remain the baseline to beat.** One user keeps six Excel sheets updated weekly, with XIRR: "никакая аналитика портфеля от брокера не нужна" (no broker portfolio analytics needed). Another wants something "минималистичная, интуитивно понятная" (minimal and intuitive) that a spouse could read if something happened to him. https://t-j.ru/looking-for-tablichka/
40. **Users cancel paid journals for Excel.** A TradeZella user cancelled, doubting it added enough value over their Excel workflow. https://uk.trustpilot.com/review/tradezella.com?page=5
41. **SaaS billing angers users.** Tradervue reviews include "will charge your credit card even if you downgrade to free plan" and "Two years after cancelling they are still billing". https://au.trustpilot.com/review/tradervue.com
42. **Daily-note friction in Obsidian.** Users have to "modify the date in the file.day line every day". Notes cannot be attached in real time because TradesViz trades "aren't synced until the next day." https://forum.obsidian.md/t/stock-trader-daily-note/56136

## 6. AI: what people want and what they distrust

43. **Bulk AI tagging is distrusted.** TradeZella's AI tagging "lag[s] badly and can apply incorrect, contradictory tags across hundreds of trades." The user adds that there is "no reliable undo or restore function." https://uk.trustpilot.com/review/tradezella.com?page=5
44. **Raw CSV pasted into an LLM is not analysis. [vendor]** TradesViz writes: "You cannot dump numbers into an LLM and get generalizable insight." AI verdicts produce "conviction attached to noise." The vendor's preferred pattern is to compute the numbers deterministically first and then let AI summarize them. https://www.tradesviz.com/blog/state-of-journaling-2026/
45. **Wanted AI analyses, with guardrails.** The analyses people want: win rate and R-multiple by setup and time, revenge trading (size increasing after losses), the disposition effect, overconfidence versus self-rated confidence, and "what if" counterfactuals such as P&L without midday trades. The risks: AI can "invent statistics, miscount trades", and samples under 20–50 trades are noise. Users should strip account numbers before pasting into a chat. https://daytradingtoolkit.com/trading-tools-tutorials/ai-trading-journal-analysis
46. **On Reddit, AI is a second opinion, not an oracle.** r/Daytrading commenters use AI to "generate leads" and to check their own work. They warn that it "works until it doesn't" and that LLMs predict text, so output must be verified. https://reddit.sudovanilla.org/r/Daytrading/comments/1jsyvut/has_anyone_done_this
47. **Users ask for local LLMs.** Wealthfolio #174 asks to "Integrate with Ollama for local GenAI features". Ghostfolio #7013 asks for "AI-generated portfolio insights using local LLM (Ollama) or OpenAI." https://issues.ecosyste.ms/hosts/GitHub/repositories/afadil%2Fwealthfolio/issues and https://www.GitHub.com/ghostfolio/ghostfolio/issues
48. **AI hallucination on factual questions.** A PP forum poster pasted an AI comparison, then said it was "likely hallucinating" about IBKR features. https://forum.portfolio-performance.info/t/do-ibkr-users-at-all-need-pp/38227
49. **AI agents need scoped, read-only access. [vendor]** TradesViz's MCP integration starts read-only, gives journal notes a separate opt-in, can be revoked, and "cannot place, change or cancel broker orders"; it warns that "AI responses can contain mistakes, so review proposed changes before approving them." https://www.tradesviz.com/blog/state-of-journaling-2023

## 7. Privacy, local-first and Obsidian workflows

50. **Cloud journals make your data hostage. [vendor comparison]** With Kinfo, data "lives on Kinfo's servers" and "a service outage means no journal access." https://journalplus.co/compare/kinfo-vs-edgewonk
51. **Local and read-only access is praised.** Rotki is praised because "It runs locally so you don't need to give all your addresses to some random website," and Getquin for "read only access." One commenter suspects CoinTracker gives data to the IRS. https://gummysearch.com/tools/best-products/portfolio-trackers/
52. **PP's local storage counts for Russian users.** It is praised as free, local, with target allocation. Its downsides: it "надо настраивать" (needs setting up), and the community is mostly German-speaking. https://t-j.ru/kakuiu-programmu-dlia-ucheta-dokhodnosti-investitsii-vybrat/
53. **Self-hosting has a cost.** TradeNote is GPL and keeps "Your trades… on YOUR infrastructure", but "Security depends on your configuration". You must set up MongoDB encryption and TLS yourself. https://prompts.brightcoding.dev/blog/stop-leaking-your-trades-to-big-tech-tradenote-exposed
54. **Portability and screen privacy.** Wealthfolio has #191 "support 'portable' mode" and #156 "toggle button to hide investments values". https://issues.ecosyste.ms/hosts/GitHub/repositories/afadil%2Fwealthfolio/issues
55. **Obsidian traders' patterns.** They keep one note per trade with frontmatter fields (symbol, entry, stop, target) and use Dataview rollups. They score conviction 1–10 before and after a trade to find "Overconfidence". Weekly reviews use Templater, and checklist snippets prompt reflection after losses. The hard numbers still live in Excel. Dataview performance on large trade sets is a concern. https://forum.obsidian.md/t/traders-share-how-youre-using-obsidian/72606
56. **Demand for "local-first trading journal for Obsidian".** Journalit keeps the journal in the vault and works offline, but trade import is backend-powered and paid, and the plugin is not open source. Several competing plugins exist: tradoshi, trade-journal, trader-journal, tradebook and trade-rythm. https://github.com/Cursivez/journalit and https://community.obsidian.md/plugins/tradoshi

## Top 10 implications for a local-first CLI + AI-agent trading journal (Python, SQLite, Obsidian export)

1. **Store raw executions and keep imports reproducible.** Keep every broker row as received (source file hash, row number, raw JSON) in an append-only `raw_fills` table. Derive trades, lots and P&L as *views* that can be rebuilt. Silent format drift (#3), dropped closing legs (#1) and 10x size errors (#2) can only be caught and fixed if you can re-run the import. Imports must be idempotent with account-scoped dedupe keys (#7).
2. **Make importers plugins, each with fixtures and a reconciliation check.** Start with IBKR Flex XML, T-Invest API/report, Tradernet/Freedom and generic CSV with a column-mapping profile. After each import, compare computed positions and cash per currency with the broker's ending balances and print a diff ("11.2 vs 15 shares", #6). FX conversions (#5), grants, `Tax Coupon` and fee rows that are not tied to a security (#10, #11) must be first-class event types, not skipped.
3. **Use an explicit event model for corporate actions and options.** Splits with ratio, mergers, spin-offs with cost allocation, symbol and FIGI changes, assignment, exercise, expiry, and rolls linked as one *campaign*. Respect the ×100 multiplier. Lot matching must cover partial fills and scale-ins (#15–#21). Let the agent *propose* a corporate-action event when positions go negative or prices jump, and require user confirmation.
4. **Make cost-basis method a reporting parameter, not something stored.** Compute FIFO, average cost and specific-lot *in parallel* from the same lots (#22). Fee treatment (in basis or as expense) is configurable (#23). Every P&L number should be explainable with `journal explain <trade>`, which shows the lots, fees, FX rate and formula. This answers "the broker's app calculates it wrong" (#29) and the 1099-vs-journal gap (#25).
5. **Keep currency and tax by jurisdiction, with dates.** Hold native-currency amounts plus FX rates with a source and date (CBR rate on the payment date, filling weekends from the previous rate; ECB; NBK). Report in any currency. Model dividends with separate foreign withholding and local tax (#31). Tax modules should emit *worksheets*, not filings: a Russian 3-NDFL table per operation (#26–#28, FIFO, income code, country from ISIN) and a Kazakhstan form-270 summary (#30). Hard-coded assumptions should be visible and overridable.
6. **AI should explain, not compute.** All statistics come from deterministic SQL. The LLM receives computed aggregates and trade IDs, never raw CSV to "analyze" (#44, #48). Every claim cites trade IDs and queries the user can re-run. Below roughly 30 trades per bucket, say "not enough data" (#37, #45). Bulk AI actions (tagging) are dry-run diffs with undo, never silent mass edits (#43).
7. **Build AI features around behaviour, not prediction.** The wanted analyses are revenge-trading detection (size after losses), rule breaks against a written plan, the disposition effect, conviction vs outcome, counterfactuals ("without trades after 2 losses"), and weekly review drafts (#45, #55). Avoid "AI picks/signals" positioning (#46).
8. **Local-first by default, with a model choice.** The SQLite file is the product: portable, with no account and no telemetry. Support a local LLM (Ollama) as well as cloud models, with an explicit redaction layer that removes account numbers and exact balances before cloud calls (#47, #49–#51, #53–#54). The agent gets read-only tools by default, and writes go through confirmed diffs. No broker order placement.
9. **Obsidian export: one-way generated data, protected user prose.** Export one note per trade and per day/week with YAML frontmatter that Dataview can query. Precomputed summary tables mean Dataview does not have to do the math (#18, #38, #55). Regenerate only fenced "generated" blocks and never overwrite the user's own notes. This removes the "maintaining the setup instead of trading" trap and the daily date-edit chore (#42). Notes should link to trades by stable IDs so they can be written before the import arrives.
10. **Design for low-effort consistency.** Five-minute post-session flow: `journal import`, then `journal review today`, where the agent asks 2–3 targeted questions (why was this trade outside the plan? emotion 1–5?) and writes the answers to Obsidian. Use gentle, non-judgemental prompts after loss days, because avoidance is the main reason people quit (#36). Weekly digest. Free and open, so it doesn't become another cancelled subscription (#40–#41). A plain overview readable by family should also be possible (#39).
